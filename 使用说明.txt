在线考试自动答题助手 —— 使用说明
=================================

一、开始之前
------------
1. 整个「自动答题」文件夹要一起拷走（里面有 _internal 子目录），只拿 exe 是跑不起来的。
2. 双击 自动答题.exe 打开界面。
3. 界面是「识别 + 点鼠标」，请确认用在你自己有权操作的环境里。

二、填大模型接口（最常出错的地方）
----------------------------------
界面第一栏「大模型接口」：

  服务商    —— 下拉选一个，地址和模型名会自动填好（推荐先这样试）
  API Key   —— 把网关给你的 Key 粘进来
  Base URL  —— 接口地址
  模型名    —— 一定要和网关匹配，这是最容易踩的坑

要点：换了网关，地址和【模型名】必须一起换。

常见的填法：
  OpenAI     https://api.openai.com/v1                          模型 gpt-4o-mini
  DeepSeek   https://api.deepseek.com/v1                        模型 deepseek-chat
  通义千问    https://dashscope.aliyuncs.com/compatible-mode/v1   模型 qwen-plus
  智谱 GLM   https://open.bigmodel.cn/api/paas/v4                模型 glm-4-flash
  自建中转    按网关文档填

关于 /v1：带不带都行，程序会自动纠正；文档里整段接口地址（.../chat/completions）
粘进来也没关系，多余的尾巴会被自动剥掉。所以不要再为此纠结。

关于模型名：地址指向 DeepSeek、模型名却还是 gpt-4o-mini，会一直报
「Model Not Exist」之类的错 —— 这就是「换了地址没换模型名」。

三、测试连接
------------
填好后点「测试连接」。它会自动试各种地址写法，并告诉你实际打通的是哪个地址。
- 成功：日志里会写 [成功] 接口可用：<实际地址>
- 失败：日志里会写试过的地址和 HTTP 状态码，并按顺序提示先查什么

四、运行
--------
1. 先勾「试运行（DRY_RUN：只识别、不点击）」，点「开始答题」跑一轮，
   确认日志里识别出的题目、选项、小圆点坐标都对。
2. 确认无误后取消勾选「试运行」，点「开始答题」。
   【容易踩】试运行是真的一个鼠标都不点。跑完日志最后会专门提醒这一点；
   界面上「开始答题」按钮旁边也一直写着当前模式：
     橙色「试运行 —— 不会点鼠标！」  = 只是演练，不会作答
     红色「正式模式 —— 会真的点鼠标。」= 会真的点，确认坐标没错再用
3. 点「开始答题」后窗口会自动最小化，倒计时内把考试页面切到前台全屏。
   【重要】答题过程中不要让本窗口挡在考试页前面：它会被一起截图，OCR 会把界面上的
   下拉框、按钮、日志文字当成题干和选项（选项会被串成一大条，整题都答废）。
   跑完窗口会自动恢复，日志一条不少。
4. 想中途停：把窗口恢复出来点「停止」（当前这一轮会尽快收尾）；或把鼠标甩到屏幕左上角。

紧急停止（浏览器全屏、切不出后台时用这个）
------------------------------------------
程序一启动就会挂上一个全局热键，跟窗口焦点无关，全屏页面里照样有效：

  连按 3 次 Esc          <- 推荐，最快
  或 按 Ctrl + Alt + Q

触发后最多 0.2 秒内就停手，日志里会写一行「【紧急停止】检测到 …」。
另外两个老办法也还在：
  * 界面上的「停止」按钮（前提是能把窗口切到前台）
  * 把鼠标甩到屏幕左上角（pyautogui 的 FAILSAFE）

停下来之后，界面窗口会自动恢复并强制弹到最前面（会短暂置顶 1.2 秒），
所以浏览器还在全屏也看得见它。

【为什么答题时切不出去】程序在跑的时候会把鼠标挪到选项上点击。这时候你 Alt+Tab
切到别的窗口，下一次点击又会把考试页拉回前台，看起来就像「切不出去」。
这是正常的：答题期间鼠标归程序用，想切出去请先停（连按 3 次 Esc 最快）。

热键写在 exam_auto_solve.py 的 PANIC_ESC_COUNT / PANIC_ESC_WINDOW / PANIC_HOTKEYS，
不想用就设 PANIC_STOP_ENABLE = False。

关于小圆点：如果页面的选项本身就带圆圈符号（形如 "○A、立即到…"），程序会直接把
圆圈中心当作点击目标，不再依赖 DOT_OFFSET_X；这种页面上 DOT_OFFSET_X 填多少都不影响。
DOT_OFFSET_X 只在「选项文字左边没有圆圈、需要往左推一段距离」时才起作用。

关于翻页（答完点「下一题」）：
  「运行参数」里有一项「答完后点页面上的「下一题」按钮翻页」，默认勾选。
  流程是：点完选项 -> 等 2 秒 -> 页面自己没跳转的话，去点识别到的「下一题」按钮；
  页面上根本没有这个按钮时，才退回原来的「按 Enter」兜底。
  * 按钮是整屏找的，不限于左侧题目区（这类按钮常压在右侧答题卡那一片）。
  * 只认「下一题 / 下一页 / 下一道 / next」这类短文字；页面底部的说明文字
    （如「答完本题后点击下一题继续作答」）不会被误当成按钮。
  * 如果你的页面答完会自动跳到下一题，就不要勾这一项，免得跳过头。
  * 【重要】点过「下一题」按钮之后，程序绝不会再补按 Enter。按钮被点过就会拿到
    键盘焦点，此时按 Enter 等于又激活它一次，页面会连跳两题、整整跳掉一道题。
    所以：按钮点了没反应就交给下一轮重试，宁可慢一轮，绝不跳题。
  * 做到本部分最后一题时，页面上往往只剩「保存」没有「下一题」。这时程序不会
    自己乱点，会在日志里提示「页面上没识别到「下一题」按钮（可能已经到本部分
    最后一题了）」。要不要交卷 / 翻到下一部分，请你自己决定 —— 交卷按钮程序绝不碰。

小圆点偏移 DOT_OFFSET_X：识别到的小圆点位置和实际要点的位置之间的横向距离，
试运行时按截图微调即可。

答题节奏（想更快就调这里）
--------------------------
「运行参数」里的「答题节奏」有三档，默认「快速」：

  极速  最快，等待最少。页面渲染慢的话可能点空（点了没反应）。
  快速  默认档。实测比老版本（标准）快一半左右。
  标准  老版本那套保守等待。你的页面很卡、点了老是没反应时再用。

每题的耗时大致是：OCR 1.5~4 秒 + 大模型 1~2 秒 + 等待（节奏档决定）。
实测同一台机器、同一份题：
  单选题  标准 5.4 秒/题  ->  快速 2.6 秒/题
  4 选项多选  标准 8.4 秒/题  ->  快速 3.8 秒/题

觉得还慢的话：OCR 是固定成本，压缩不了多少；真要再快就上「极速」，
或者把「保存每轮截图到 debug_shots/」取消勾选（省一点点磁盘 IO）。

五、命令行自检（出问题时用）
----------------------------
打开 PowerShell，cd 到本文件夹：

  不点鼠标、不联网，只自检 OCR 和题目解析：
    & '.\自动答题.exe' --selftest

  不开界面，拿同目录 config.json 直接打一次接口，排错用：
    & '.\自动答题.exe' --test-api

六、配置文件
------------
界面上点「保存配置」会写同目录的 config.json（明文保存，包含 API Key，别外传）。
删掉它就会回到默认值。

七、出错了怎么办
----------------
- 界面日志区、以及同目录的 exam_auto_solver.log 里有详细记录。
- 程序崩溃会写 crash.log，并把错误弹窗给你。
